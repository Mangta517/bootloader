# 串口恢复升级

本工程位于 `0x08004000–0x08007FFF`，容量 16 KiB，需由前级程序跳转进入。向量表偏移为 `0x4000`。进入后持续等待升级命令。

升级目标为 `0x08008000–0x0807FFFF`，最大 BIN 长度为 491520 字节（480 KiB）。接收前按 BIN 长度擦除目标扇区，升级过程会覆盖目标 APP。

## 串口操作

USART1：115200、8 数据位、无校验、1 停止位、无流控。PA9 为 TX，PA10 为 RX，USB 转串口与板卡共地，使用 3.3 V TTL 电平。

1. 进入恢复程序，串口显示 `[BOOT] start:len`。
2. 以文本发送 `start:实际BIN字节数`，例如 `start:4484`。命令结束由串口空闲标志识别，可附加 CR/LF；命令与 BIN 必须分开发送。
3. 等待 `Flash erased; send data`，此时 DMA 已启动，再以原始二进制文件方式发送 APP 的 `.bin`。
4. 文件发送完毕后，底层确认串口空闲且当前数据处理完毕，记录完成时间戳；再等待 2 秒无新数据，程序自动停止接收并补写奇数长度的最后一个字节。新数据到来会清除时间戳，重新确认空闲并计时，无需按键。
5. 接收长度、UART/DMA 和 Flash 状态检查通过后显示 `ok,len:实际字节数`，随后跳转到 APP。检查失败则打印错误并复位。

沿用现有 `start:长度` 协议，不含 CRC 校验；长度检查通过不能证明传输内容与原文件逐字节一致。

## APP 要求

APP 必须重新链接到 `0x08008000`，Flash 容量设为 `0x78000`，向量表偏移设为 `0x8000`。当前跳转函数关闭全局中断后进入 APP，APP 应在设置自身向量表后、HAL 初始化前执行 `__enable_irq()`。APP 时钟配置需与当前 HSE 8 MHz、PLL 168 MHz 的交接方式兼容。

不要使用链接在 `0x08000000` 或 `0x08004000` 的 BIN 作为升级目标。

## 验证

在工程根目录运行 `python -B tools/test_uart_ring.py`，可验证实际 C 代码的 DMA 接收、2 秒自动收尾、续传重新计时、tick 回绕、跨扇区写入、奇数字节收尾、容量限制和错误路径。

Keil 编译和主机模拟不代替板上串口收发、Flash 写入和 APP 跳转验证。
